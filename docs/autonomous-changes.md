# CHANGES: every bug found and fixed in the 2026-11 hardening run

Each entry: what was wrong, how it was found, the fix, and the test that now covers it. Bugs are ordered roughly by how real they were for a visitor.

| # | Bug | Found by | Fix | Test |
| --- | --- | --- | --- | --- |
| 1 | **Anything with `%00` in a search phrase, a filter, the "by" artist or a list note answered 500** (Postgres refuses NUL in text and JSON) | seeded input fuzzing | `stripControl()` before the value is used (`src/lib/text.ts`, `http.ts`, `service.ts`, the lists routes) | `tests/unit/input-fuzz.test.ts` |
| 2 | A string of emoji just over the limit passed the length check (Zod counts code points) and was then cut at 100 UTF-16 units, splitting a character: `encodeURIComponent` threw, **500**. The finder's URL state also could not read back what it wrote after such a cut | fuzzing (round-trip property) | `cut()` never splits a surrogate pair; `text()` trims after cutting | `tests/unit/input-fuzz.test.ts`, `tests/unit/finder-state.test.ts` |
| 3 | The proxy matcher `"/((?!api\|_next\|_vercel\|ds\|.*\..*).*)"` had a single backslash in a JS string (which is just `.`), so it skipped every path with a character and ran on `/` only; locale handling never ran on `/en/...` pages | writing the CSP (every page but `/` had no policy) | doubled backslash | `tests/unit/proxy-csp.test.ts` (matcher cases) |
| 4 | On a 375x667 phone the delete-account sheet (and the remove confirmation) sat 40 px too low and its last button was cut off by the bottom of the screen: the design system's closed-state `translateY(40px)` has the same specificity as, and comes after, its open rule | `tests/e2e/phone-menus.spec.ts`, already failing on `main` | override in `ds-extensions.css` (`public/ds` untouched) | `tests/e2e/phone-menus.spec.ts` |
